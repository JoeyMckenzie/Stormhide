# Stormhide architecture

How the code is organised, so a new session can start a feature without reading every file. For *why* things work this way under Midnight's combat restrictions, see [api-research.md](api-research.md). For what to build, see [design.md](design.md).

## Files (load order, from `Stormhide.toc`)

| File | Owns |
|------|------|
| `Locales/enUS.lua`, `Locales/zhCN.lua`... | Translations (see **Localization** below). Load first, before Stormhide.lua |
| `Stormhide.lua` | Core: the HUD frame (`ns.hud`, 240×240), shared sizes, saved settings, slash commands, debug helpers |
| `Profiler.lua` | `/stormhide perf`: times Stormhide's own code. `ns.Profiled(module)` returns a `CreateFrame` and `C_Timer` for that module; every runtime file starts with `local CreateFrame[, C_Timer] = ns.Profiled("<File>")`, so its plain frames (type `Frame`, no template) time each script they run (OnEvent keyed by event name) and its timer callbacks are timed too. Off, a wrapper only checks a flag. Reports ms of our code per second of play, in and out of combat, plus Blizzard's `C_AddOnProfiler` numbers if the client has them; saved in `StormhideDB.perfReports` (last 10). Loads right after Stormhide.lua, before every file it times. The settings window, Edit Mode and AddOns page files aren't timed (they only run while open) |
| `SpellTiming.lua` | What we know about spell timing, shared by the GCD pie, the cooldown rings and the cooldown box: `ns.GCD_SPELL`, `ns.GcdRunning`, `ns.CooldownState` (a real cooldown is `isActive and isOnGCD ~= true`, verified in combat 2026-10-10). Catnip's learned GCD and cooldown lengths (`ns.LearnedLength`/`ns.LearnLength`) and `ns.ReadCooldown` were removed 2026-11-14 with the swing-paced GCD pie, their only user |
| `RadialBar.lua` | Radial StatusBars (verified on Forever 2026-10-10, offsets and directions measured; [api-research.md](api-research.md)): `ns.CreateRadialBar(parent, art, layer)` returns `bar, texture` (the bar fills `parent`), `ns.ShapeRadialBar(texture, from, span, fill, clockwise)` (maths radians; `from` is where the moving edge starts, `clockwise` the way it moves; anchors the bar at `from` when filling or at the far end when draining, and sets Reverse, which mirrors the arc about its anchor), `ns.RunRadialBar(bar, duration, fill)` (Blizzard times it from a duration object), `ns.SetRadialBarValue(bar, value)` (stops the timer, holds a value), `ns.Duration(start, seconds)` (a duration object from plain numbers). Used by SegmentedArc.lua and Cast.lua |
| `Elements.lua` | The element registry for customisation ([settings-plan.md](settings-plan.md)): `ns.ZONES` (the settings window's zones: Above, Circle, Below, each listing elements in `groups` by the elements' `zone` field, a named group getting a heading), `ns.RegisterElement`, `ns.GetElement`, `ns.ElementOption` / `ns.ElementStored` / `ns.SetElementOption` / `ns.ResetElement` / `ns.ResetAllElements`, stored in `StormhideDB.elements[id][key]` (nil = default, or General's value for an `inherit` option; shared across Edit Mode layouts). Every element's `apply(get)` runs on load and after any change. Also the font helpers: `ns.FONTS` (Blizzard fonts only), `ns.OUTLINES`, `ns.ApplyFont(fontString, font, size, outline)` (falls back to the standard font if a file doesn't load), `ns.FontObject(font, size)` (a cached Font object, for text that refuses `SetFont`, like Blizzard's menu labels), `ns.TextOptions(defaultSize)`, and the `general` element (font, outline). An element's optional `order` sorts it within its group in the settings list (the combo rings use their dot's number); `glyph` (`{ kind = "disc" | "ring" | "arc" | "dots" | "text", color = { r, g, b } }`) its icon. An option may have `get`/`set` (stored elsewhere, e.g. on a combo ring's ability) and `enabled` (a function; the choice control dims and ignores the mouse while false); an element may have `onReset` (before Reset to defaults). `hidden = true` keeps an element's code and options but doesn't offer it: not listed in the settings, not outlined in preview mode, and stored values ignored (defaults only); hidden: Resource circle, Mana prediction, Five-second ring, GCD pie. The swing time and the cast time and name are one element, `text.under` "Swing/Cast Timer" (Cast.lua: Timer size for both times, Spell name size; `text.swing` and `text.castTime` kept, hidden, for their samples). Options can be `hidden` too (control not shown, stored value ignored): font and outline on every text element, and the `general` element as a whole (so the Rotation tab has no General zone: Options.lua adds it only while `general` isn't hidden); text elements offer only Size. Its optional `hit` shape (`{ kind = "circle", radius, x, y }` in HUD units from the centre, or `{ kind = "ring", inner, outer, angle, spread }`, a band round the centre, optionally only within `spread` of maths angle `angle` (6 o'clock is -pi/2; the outline is cut to it with two `half_plane` masks); `{ kind = "circles", radius, centres = fn }`, several circles picked and outlined as one (the dots); circles and rings may have `visible = fn`; or `{ kind = "text", region, anchor, point, y, chars, below }`: a box of our own at the text's anchor, sized from its Size option (`size`) plus `below` (a second line's height); any of region, anchor, y, chars and below may be a function, read each refresh, since a FontString showing a secret value has a secret rect) makes it pickable in preview mode. `sample(state)` draws preview mode's sample (nil: back to the real one). Loads right after Stormhide.lua so modules can register at file load |
| `Preview.lua` | `ns.Preview`: preview mode, on while the settings window shows the Rotation tab (`SetWanted`), out of combat and outside Edit Mode (Blizzard's or Stormhide's, polled every 0.25s). On a layer at hud +30 (ignores the HUD's opacity): every element with a `hit` gets an outline (circle: `circle_feather` + `ring_thin` tinted blue; ring: `ring_bar` sized to the band plus `ring_thin` at both edges; text: Edit Mode's nine-slice via `ns.ApplyEditModeLook` on the text's box), faint when idle, bright when hovered on the HUD or in the settings tree (`SetListHover`), yellow/gold when its page is open (`SetSelected`). Hover shows a tooltip; a click calls `ns.OpenElementSettings`. While active the HUD shows one sample state (`"shaman"`; Catnip's Caster / Bear / Cat states and Stealth toggle were removed 2026-11-14): every element's `sample(state)`, and `sample(nil)` when it ends. Samples: Resource.lua (80% of the real max mana), Swing.lua (a 3.5s swing looping on the ring and text; real swings noted but not drawn), Cast.lua (no cast: hides the cast ring so the swing shows; real cast events wait), Gcd.lua (a 1.5s sweep every 2.5s), FiveSecondRule.lua (a made-up spend every 6.5s), ComboPoints.lua and ComboRings.lua (each ring's looping sample in its slot). While the circle shows a sample (`ns.IsResourceSampled()`), ManaPrediction.lua hides its bands |

## Shared namespace (`local addonName, ns = ...`)

**Core (`Stormhide.lua`)**
- `ns.hud`: the frame everything draws in. Layout.lua positions and scales it.
- Sizes: `ns.RESOURCE_SIZE` (100), `ns.SWING_RING_SIZE` (134), `ns.TIME_TEXT_OFFSET` (104: top of the cast and swing time text, below the HUD centre). `ns.MEDIA`: texture folder path.
- `ns.db`: saved settings (`StormhideDB`), ready inside `ns.OnLoad` callbacks. Modules add defaults to `ns.defaults` at file load.
- `ns.char`: this character's settings (`StormhideDB.chars[<player GUID>]`, with a `name` field to tell them apart in the saved file), ready inside `ns.OnCharacterLoad` callbacks (`PLAYER_LOGIN`), not `ns.OnLoad`. Keyed by GUID because `UnitName` returns the account-wide first name, the same for every character (2026-10-08). Event handlers that use it must return early while it is nil (`SPELLS_CHANGED` can come before `PLAYER_LOGIN`). For what depends on the character's spells and talents: the tracked cooldowns (`cdTracked`), `cdLastPotion` and learned `lengths`. To make another key per-character, add it to `CHARACTER_KEYS` in `Stormhide.lua` (which moves an old account-wide value to the first character that logs in) and read it from `ns.char`. Everything else is account-wide.
- `ns.OnLoad(fn)`: run `fn` once saved settings are loaded (`ADDON_LOADED`).
- `ns.SettingsChanged()` after changing a setting; `ns.OnSettingsChanged(fn)` to react (the settings window refreshes on it). To add a setting for a HUD element (its look: opacity, text, formats), add an option to its `ns.RegisterElement` spec in the owning module and handle it in `apply`; the Rotation tab builds the control. Other settings: default in `ns.defaults`, an apply function in the owning module, a control in `Options.lua`.
- `ns.commands.<name> = fn(arg)`: adds `/stormhide <name> <arg>`. `ns.commands[""]` is plain `/stormhide`. Update the help text in `Stormhide.lua` when adding one: player commands in the plain help, testing and dev tools under `/stormhide dev`.
- `ns.Print(...)`, `ns.Debug(...)` (only with `/stormhide debug` on; secret-safe), `ns.Describe(v)`, `ns.IsSecret(v)`.
- `ns.TryRegisterEvent(frame, event)`: registers an event that may not exist in this client; returns success.
- `ns.SPELL`: the spells we look for, by the ID of any rank (`ns.SPELL.EARTH_SHOCK`). **Never look a spell up by an English name**: other clients name spells in their own language (see **Localization** below).
- `ns.SpellName(spell)`: the client's name for an `ns.SPELL` entry (cached; nil while unknown).
- `ns.FindKnownSpell(spells)`: ID of the first of `spells` in the spellbook, at the highest rank known (looked up by the client's name for it, then `IsPlayerSpell`), else nil.
- `ns.IsSpellNamed(name, spells)`: whether a spell name (e.g. a cast's, from `C_Spell.GetSpellName`) belongs to one of `spells`, any rank or form version. False for a secret name.

**Spell timing** (SpellTiming.lua; loads right after Stormhide.lua, so usable anywhere)
- `ns.GCD_SPELL` (29515): the spell Forever reports the GCD on. `ns.GcdRunning()`: from the readable `isActive`.
- `ns.CooldownState(spellID, previous)`: `onCooldown, sure` for a real cooldown (not the GCD): `isActive and isOnGCD ~= true`, both readable in combat (verified 2026-10-10); `previous` comes back when they're secret. Used by Cooldowns.lua and SegmentedCooldown.lua.

**Features**
- `ns.CreateAuraContainer{ label, unit, filter, spellIDs, width, height, x, y, relativeTo, level, parent, initialize }` and `ns.HideAuraButtonArt(button)` (AuraContainer.lua). `ns.HAS_AURA_CONTAINER`. ## Patterns to reuse

- **Showing a secret number**: pass it straight to `StatusBar:SetValue`/`SetMinMaxValues` or `FontString:SetText`/`string.format`. Never compare or do math on it.
- **Showing an aura in combat** (buff on player, debuff on target): `ns.CreateAuraContainer`. Blizzard shows a button while the aura is up; our look goes on the button in `initialize` and must be static after that (the button and its children are off-limits to our code later). For a timer, create a `Cooldown` in `initialize` and register it with `button:SetDurationCooldown(cooldown)`: Blizzard drives it with the real duration. Examples: `Proc.lua` (static cap), `DotRings.lua` (timer rings).
- **Filling a round shape from the bottom**: a vertical `StatusBar` with a flat or baked-gradient texture, masked (`CreateMaskTexture` + `AddMaskTexture`) to a circle or ring. Example: `Resource.lua`.
- **Arcs growing along a ring from any point** (a Cooldown swipe always starts at 12 o'clock): per side, a clip frame (`SetClipsChildren(true)`) showing half the ring, holding a half-ring texture that `SetRotation` swings into view. Example: `FiveSecondRule.lua` (two arcs anchored at 6 o'clock, shrinking from 12). For anything timed, a radial StatusBar (next) does this without Lua per frame.
- **Showing something depending on a secret number** (e.g. "how many casts can my mana pay for"): one pre-built variant per outcome, each with alpha from a step curve evaluated engine-side (`UnitPowerPercent(unit, powerType, false, curve)`, curve x is the fraction of max) that's 1 only in that outcome's range. Example: Catnip's `ShiftOrbs.lua` (centred rows of 1-5 orbs; removed from Stormhide, at commit `0ea2f9c`). If the thing already animates its own alpha, put the curve on a parent frame instead (effective alpha multiplies).
- **Filling or draining a fixed, coloured arc or ring over a timer** (colour baked by position, so the art can't rotate): a radial StatusBar (RadialBar.lua) showing the art, limited to the arc with its start and end offsets and run by `SetTimerDuration` from a duration object, so Blizzard times it exactly, secret or not, and no Lua runs per frame. Fills or drains in either direction. Segments and gaps go in the art. Examples: `SegmentedArc.lua` (`CooldownRings.lua`), `Cast.lua`. (Until 2026-10-10: the art masked by rotated `half_plane` masks, one wedge per segment, moved by our own clock.)
- **Resizing a frame from a corner**: `StartSizing` misbehaved on the settings window (jerky, then jumped to the maximum height; 2026-10-02), even after anchoring by the opposite corner. `Options.lua` now does its own drag: pin the top-left corner, then each frame set the size to the size at the press plus the cursor's movement (in the frame's scale), clamped to the screen. The cooldown box's corner grips (`Cooldowns.lua`) still use `StartSizing` and may need the same.
- **Resizing something built from AuraContainer buttons**: build at a fixed size and `SetScale` the frame they live in; the buttons themselves are forbidden after setup. Example: `Cooldowns.lua`.
- **Moving decoration on an AuraContainer button**: a looping animation started once with `Play()` at setup (no `OnShow`/`OnHide` handlers: blocked on these buttons). For motion a rotation can't do (dashes running around a square), a `FlipBook` animation over a grid of pre-drawn frames. Example: `Cooldowns.lua` (`square_dashed`).
- **Timer rings**: a `Cooldown` frame with `SetSwipeTexture(<ring texture>)`, `SetDrawEdge(false)`, `SetDrawBling(false)`, `SetHideCountdownNumbers(true)`. Starts full and empties clockwise. Plain-number timings go to `SetCooldown`; secret ones need a duration object (`SetCooldownFromDurationObject`). A spell's cooldown without the GCD is `C_Spell.GetSpellCooldownDuration(id, true)`.

## Localization

Every piece of text a player sees goes through `local L = ns.L` (each file sets it under `local addonName, ns = ...`): `L["Reset to defaults"]`. The key is the English text; `Locales/enUS.lua` makes a missing key return itself, so English needs no entries and untranslated text shows in English. Other languages are `Locales/<locale>.lua` files (zhCN so far), each starting `if GetLocale() ~= "<locale>" then return end` and listed in `Stormhide.toc` after enUS.

- **After changing any text, run `py tools/locales.py`.** It rewrites each language file from the code: translations kept, new keys added as commented placeholders grouped by the file that uses them, translations whose English is gone moved to a "No longer used" section. `--check` changes nothing and exits 1 if a file is out of date (`.github/workflows/locales.yml` runs it on every push and pull request that touches Lua, so a stale file fails the build); `py tools/locales.py zhTW` starts a new language. Changing English wording orphans its translation, so reword deliberately.
- Write keys as plain double-quoted literals (`L["..."]`, never `L[variable]`), or the script can't find them.
- Text built from parts is a format string, so a translator can reorder it: `L["Reset %s"]:format(name)`, not `"Reset " .. name`.
- **Spell names come from the game, not `L`**: `ns.SpellName(ns.SPELL.EARTH_SHOCK) or "Earth Shock"` (the English fallback only covers spell data not being loaded). A phrase containing a spell name is one key (`L["Shifting Power ready pulse"]`); the translator writes the spell's name in.
- **Display text is never an ID.** Things keyed by name get an untranslated key next to the label: `topTabs.Add(L["General"], "General")` (the side tab icons are looked up by the second). Element `label`s on AuraContainer, SegmentedCooldown and ActionBar specs only reach debug output and stay English; the combo ring dropdown text is a separate `choice` field.
- Left in English: `ns.Debug` output, `/stormhide dev` tools and their output (`perf`, `spells`, `item`, `art`, `icon`, the ring previews), slash command names, font names.
- **Adding a language:** `py tools/locales.py <code>` (e.g. `deDE`) creates the file with every key as a placeholder; then add `Locales\<code>.lua` to `Stormhide.toc` after the others. Volunteers can ask on the Discord rather than use GitHub (README "Translations"); the CurseForge description (`docs/curseforge.md`) points there too. CurseForge's own translation site, injected by the packager's `@localization@`, is the fallback if several translators who don't use GitHub join.

**Open items** (zhCN translated by dodoels, PR #1, 2026-10-15; they report back on a Chinese client. To ask them: Rake as 扫击 and Enrage as 狂怒 may not match the client's own names (斜掠, 激怒?), and Swing Time 攻击计时 vs Swing Timer 平砍计时条):
- **Fonts.** `Elements.lua` offers Friz Quadrata (`STANDARD_TEXT_FONT`, which is a CJK font on a zhCN client), Arial Narrow, Skurri and Morpheus by file path. The last three may lack Chinese glyphs or not exist there, so spell names in the cast text could show as boxes. Possible fixes: offer only the standard font on CJK clients, or use the zhCN client's own font files. The label "Friz Quadrata" is also wrong there; "Game Default" would fit every locale.
- **Widths.** Fixed-width spots to check: side tabs, the reset dialog, the Cooldown drop box.
- **Spell lookups on zhCN.** The Earth Shock ring. Also unverified: that `C_Spell.GetSpellInfo(<localized name>)` returns the highest known rank there as it does in English.
- **`%2$d` reordering** (mentioned in zhCN.lua's header) is unverified in this client; only "%s will move to combo point %d after combat." has two placeholders.
- Small gaps, left as is: the AddOns list description (`## Notes:` in `Stormhide.toc`, read before any Lua runs, so only a `## Notes-zhCN:` line could translate it) stays English (owner, 2026-10-15); `CooldownItems.lua`'s `ItemName(itemID):find("Potion")` only matches English (a fallback after the subclass check); nameless items and spells fall back to English "item 123" / "spell 123"; GCD lengths are learned by spell name, so switching client language relearns them.

## Debugging and testing

The user tests in-game; Claude can't run the game. Each change ends with exact steps and what to look for.

- `/stormhide debug` toggles grey debug lines (saved). Modules print startup facts, e.g. which detection method is active.
- `/stormhide perf start [label]`, play (in and out of combat), `/stormhide perf stop`: prints the top 15 rows of time spent in Stormhide's code (ms per second of play, in combat and out, calls, average and worst call) and saves the full report in `StormhideDB.perfReports`. Plain `/stormhide perf` shows the report so far while measuring. For before/after comparisons, run the same activity under two labels. Times are inclusive (a handler that calls another module's callback counts its time), and the shared factories count under their own file (every arc's clock is `SegmentedCooldown OnUpdate`). A new runtime `.lua` file needs the `ns.Profiled` line at its top to be timed.
- `/stormhide spells` lists every spellbook entry and why the Cooldowns tab offers it or not.
- `/stormhide item <id or shift-clicked link>` shows an item's class/subclass, use spell, whether it counts as a potion, and its raw cooldown.
- `/stormhide art` (typed with the mouse over a Blizzard window) records every texture in that window (debug name, layer, atlas or file ID, size, tex coords, colour) into `StormhideDB.artDump[<window>]`. After a `/reload`, read it from `_classic_beta_\WTF\Account\<account>\SavedVariables\Stormhide.lua`. For reusing Blizzard's art.
- `/stormhide icon` (typed with the mouse over an icon, e.g. in the macro icon picker) prints that icon's file ID with a preview, and keeps the last 10 in `StormhideDB.iconPicks`.
- Errors: BugSack is **not** installed in the Forever client (checked 2026-09-27); ask the user for the full error text.
- `/reload` picks up code, `.toc` file lists and textures, but **not a new `## SavedVariables` name** (probably needs a restart); keep new saved data inside `StormhideDB`.
- To verify an unknown API, add debug output that prints what the game actually returns (with `ns.Describe`, which shows `<secret>`), test in and out of combat, then record the result in api-research.md.

2. **[Cooldown Manager Centered](https://www.curseforge.com/wow/addons/cooldown-manager-centered)** (CMC, by WilduTools): the most popular skin and extension for Blizzard's Cooldown Manager (6.8M downloads), with Retail and Forever (1.60.x) builds. The reference for styling and extending the built-in Cooldown Manager. There's no official repo; [andi-74/cooldownmanagercentered-mirror](https://github.com/andi-74/cooldownmanagercentered-mirror) is a third-party GitHub mirror (the addon zip is attached to each GitHub release, not in the repo; it covers Forever too, which its code calls "Camelot"), or download the Forever file from CurseForge.
3. **[Forever Cooldown Manager](https://www.curseforge.com/wow/addons/forever-cooldown-manager)** (by Thunderz96; source at [Thunderz96/ForeverCDM](https://github.com/Thunderz96/ForeverCDM)): a Forever-only replacement for the Cooldown Manager that builds cooldown and buff icon rows from the spellbook and the player's auras, with no libraries. Its description says Blizzard's Cooldown Manager "has no spells to show for most classes" on Forever yet, and that it stays within combat restrictions by giving hidden timing values directly to Blizzard's cooldown widget without reading them (unverified by us).
4. **Blood in the Water** (another Forever Feral addon), installed locally at `C:\Program Files (x86)\World of Warcraft\_classic_beta_\Interface\AddOns\BloodInTheWater\`. Its comments document many Forever quirks; it's where the AuraContainer technique came from.
5. **[EnhancedCooldownManager](https://github.com/argium/EnhancedCooldownManager)**: the Cooldown Manager reading technique.
6. **ForeverAuras** (a WeakAuras port for Forever, v0.70.34-BETA.1), installed locally at `_classic_beta_\Interface\AddOns\ForeverAuras\`. The reference for spell cooldowns under secrets (`SpellCooldown.lua`, `GenericTrigger.lua` around `secretPoller` and `InitCooldownReady`), engine-driven timers and text (`SecretAuraSingle.lua`, `DurationText.lua`, `ProgressTextureNative.lua`) and restriction-state tracking (`Secrets.lua`, `ClientAPI.lua`). What we learned is in [api-research.md](api-research.md#from-foreverauras-unverified-by-us).

## Releasing

1. Bump `## Version` in `Stormhide.toc` (e.g. `0.1.0-beta.3`).
2. The user commits, pushes, then tags and pushes the tag: `git tag v0.1.0-beta.3`, `git push origin v0.1.0-beta.3`.
3. `.github/workflows/release.yml` builds `Stormhide-<tag>.zip` (a `Stormhide/` folder) and publishes it on the Releases page. Tags containing `-` become pre-releases. `.gitattributes` keeps dev files (`docs/`, `tools/`, every `.md` file including `README.md`, etc.) out of the zip. `LICENSE` (MIT) must stay in the zip, since MIT requires the notice to ship with copies, so never add it to either ignore list. A second job runs the [BigWigsMods packager](https://github.com/BigWigsMods/packager) to upload the same tag to CurseForge: it needs the `CF_API_KEY` repository secret (a CurseForge API token) and `## X-Curse-Project-ID` in `Stormhide.toc`, and is skipped while the secret is unset. Its ignore list is in `.pkgmeta`; keep it in step with `.gitattributes`. Tags containing `alpha` or `beta` upload as that release type.
4. Keep `README.md` (player-facing install and usage) in sync with features.
5. Keep `docs/curseforge.md` in sync too: it's the master copy of the CurseForge project description, which can only be edited by hand on the site (CurseForge has one description for all languages and no API to update it, 2026-10-15). When it changes, the user pastes it into the project's description editor.
